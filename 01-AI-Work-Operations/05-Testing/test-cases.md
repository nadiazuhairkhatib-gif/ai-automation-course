# حالات الاختبار — Test Cases

## الهدف

لا نعتبر الـ Workflow ناجحًا لأنه أعطى نتيجة صحيحة مرة واحدة.

نريد أن نعرف:

* هل يعمل مع حالات مختلفة؟
* متى يفشل؟
* كيف نكتشف الفشل؟
* ماذا نفعل عندما تكون المعلومات ناقصة أو غامضة؟

لذلك نستخدم **Test Cases**.

---

# ما هو Test Case؟

كل حالة اختبار تحتوي على:

1. **Input** — المدخل
2. **Expected Output** — النتيجة المتوقعة
3. **Actual Output** — النتيجة التي أعادها النظام
4. **Result** — ناجح أو فاشل
5. **Evidence** — الدليل
6. **Notes** — ملاحظات

---

# Test Case 01 — معلومات مكتملة

### Input

يحتوي النص على:

* Action
* Owner
* Deadline
* Decision

### Expected Output

يجب استخراج المعلومات الأربع بشكل صحيح.

### Failure to watch

اختفاء أحد الحقول أو تغيير قيمته.

---

# Test Case 02 — المسؤول غير مذكور

### Input

يوجد Action واضح، لكن لا يوجد شخص مسؤول.

### Expected Output

يجب ألا يخترع النظام اسمًا.

### Failure to watch

أن يختار AI شخصًا من سياق الاجتماع بدون دليل.

---

# Test Case 03 — الموعد غير مذكور

### Input

يوجد Action وOwner، لكن لا يوجد Deadline.

### Expected Output

يجب تمثيل الموعد على أنه غير محدد.

### Failure to watch

اختراع تاريخ أو افتراض موعد.

---

# Test Case 04 — قرار غير محسوم

### Input

النص يقول إن القرار ما زال قيد النقاش.

### Expected Output

يجب ألا يسجل النظام القرار باعتباره قرارًا نهائيًا.

### Failure to watch

تحويل اقتراح أو نقاش إلى قرار مؤكد.

---

# Test Case 05 — معلومات غامضة

### Input

الجملة يمكن تفسيرها بأكثر من طريقة.

### Expected Output

يجب الحفاظ على حالة عدم اليقين أو إرسال الحالة للمراجعة البشرية.

### Failure to watch

اختيار تفسير واحد وكأنه حقيقة مؤكدة.

---

# Test Case 06 — مهمة غير مباشرة

### Input

المحضر يحتوي على قرار أو ملاحظة تشير ضمنيًا إلى إجراء مطلوب.

### Expected Output

يجب على الطالب تقييم ما إذا كان من الآمن اعتبارها Action Item.

### Failure to watch

تحويل كل جملة في الاجتماع إلى مهمة.

---

# Test Case 07 — معلومات متعارضة

### Input

يظهر في النص أكثر من معلومة متعارضة حول نفس المهمة.

### Expected Output

يجب عدم اختيار معلومة واحدة عشوائيًا.

يجب الإشارة إلى التعارض وإرساله للمراجعة.

### Failure to watch

إخفاء التعارض وإنتاج نتيجة واحدة تبدو مؤكدة.

---

# Test Case 08 — نص بدون Action Items

### Input

محضر الاجتماع يحتوي على نقاشات فقط ولا يحتوي على مهام واضحة.

### Expected Output

يجب أن تكون النتيجة:

**No clear action items found**

وليس اختراع مهام من محتوى النقاش.

### Failure to watch

تحويل الأفكار أو النقاشات إلى مهام لم يطلبها أحد.

# معيار النجاح

لا يكفي أن تكون النتيجة صحيحة.

يجب أن يستطيع الطالب تحديد:

> **ماذا توقعت؟**

ثم:

> **ماذا حدث فعلًا؟**

ثم:

> **هل يوجد فرق؟**

ثم:

> **ما الدليل؟**

هذه هي بداية **Diagnostic Thinking**.

# قاعدة مهمة

> **Failure is not the opposite of learning. Failure is evidence.**

الفشل هنا ليس شيئًا نخفيه.

نستخدمه لفهم النظام وتحسينه.
